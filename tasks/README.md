# Tasks

This directory will contain task definitions and examples used in experiments and evaluations.

## Purpose

Tasks represent concrete software engineering work that agents will be evaluated on. Tasks provide:

- **Reproducible scenarios** — Consistent evaluation benchmarks
- **Measurable outcomes** — Clear criteria for success
- **Example variations** — Different complexity levels and domains
- **Baseline data** — Human performance or prior results

## Task Categories

Future tasks may include:

- **Implementation tasks** — Building features from specifications
- **Refactoring tasks** — Improving existing code
- **Debugging tasks** — Finding and fixing bugs
- **Testing tasks** — Writing and improving tests
- **Documentation tasks** — Creating or updating documentation
- **Architecture tasks** — Designing components or systems

## Task Template

When tasks are defined, they will include:

- **Task ID** — Unique identifier
- **Title** — Descriptive title
- **Description** — Full task description
- **Domain** — What domain this belongs to
- **Difficulty** — Estimated complexity level
- **Requirements** — What must be accomplished
- **Acceptance Criteria** — Definition of done
- **Example Inputs** — Input materials or specifications
- **Time Estimate** — Expected time for completion
- **Metrics** — How to evaluate success
