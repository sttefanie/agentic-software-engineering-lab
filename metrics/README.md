# Metrics

This document defines candidate metrics for evaluating agentic software engineering workflows.

⚠️ **Important:** These are **candidate metrics**, not yet finalized. Exact definitions, measurement procedures, and thresholds for evaluation will be established before experiments begin.

## Candidate Metrics

### Token Usage Metrics

- **Input Tokens** — Tokens consumed in input context
- **Output Tokens** — Tokens generated by the model
- **Total Tokens** — Sum of input and output tokens
- **Estimated Cost** — Estimated API cost based on token usage

### Context Metrics

- **Files Available** — Total files that could have been included
- **Files Loaded** — Total files actually included in context
- **Relevant Files Loaded** — Files that contributed to successful implementation
- **Irrelevant Files Loaded** — Files that did not contribute (noise)
- **Required Context Missed** — Information that should have been included but wasn't
- **Context Size** — Total tokens used for context
- **Context Efficiency** — Ratio of relevant to total context

### Planning Metrics

- **Planning Iterations** — Number of plan revisions before implementation
- **Planning Accuracy** — Degree to which initial plan matched actual implementation
- **Planning Efficiency** — Tokens used in planning phase

### Implementation Metrics

- **Implementation Iterations** — Number of revision cycles
- **Implementation Time** — Wall clock time to complete implementation
- **Code Quality Score** — Static analysis or review-based quality metrics
- **Lines of Code** — Volume of code generated
- **Code Efficiency** — Ratio of quality to implementation effort

### Testing Metrics

- **Tests Generated** — Number of tests created by agent
- **Test Pass Rate** — Percentage of tests passing
- **Test Coverage** — Code coverage achieved by generated tests
- **Test Quality** — Assessment of test appropriateness

### Architecture Metrics

- **Architecture Violations** — Cases where generated code violates defined boundaries
- **Architecture Compliance** — Percentage of implementation adhering to constraints
- **Coupling** — Measure of inter-component dependencies
- **Cohesion** — Measure of within-component relatedness

### Quality Metrics

- **Security Findings** — Security issues identified in generated code
- **Bug Count** — Bugs found during testing or review
- **Technical Debt** — Debt accumulation assessment
- **Maintainability** — Code maintainability score

### Task Completion Metrics

- **Task Completion Rate** — Percentage of tasks completed successfully
- **Requirement Coverage** — Percentage of requirements met
- **Human Interventions** — Number of times human had to correct or guide
- **Time to Completion** — Wall clock time to complete task

### Comparative Metrics

- **vs. Human Performance** — Comparison to human developer baseline
- **vs. Full Context Baseline** — Comparison to approach without routing
- **vs. Prior Approach** — Improvement over previous method

## Metric Definition Process

Before each experiment:

1. Select relevant candidate metrics
2. Define exact measurement procedure (not just name)
3. Establish baseline or expected range
4. Define pass/fail thresholds (if applicable)
5. Document how to detect and handle outliers
6. Document limitations of each metric

## Next Steps

As experiments are planned, specific metrics will be selected and formally defined with precise measurement procedures.
