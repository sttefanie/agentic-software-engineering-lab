# Limites Arquiteturais e Regras de Dependência

**Status: SYNCHRONIZED WITH ACCEPTED ADRs**

## Domínio

O domínio pode conter:

- entities;
- value objects;
- domain services;
- domain exceptions;
- regras de negócio.

O domínio não deve depender diretamente de:

- FastAPI;
- SQLAlchemy;
- PostgreSQL;
- HTTP;
- adapters;
- infraestrutura.

## Application

A camada de application pode conter:

- use cases;
- application services;
- ports;
- orchestration.

A application pode depender do domínio, mas não deve depender diretamente de adapters concretos.

## Adapters

Os adapters são responsáveis por integração com:

- HTTP;
- persistence;
- serviços externos;
- outras tecnologias externas.

## Direção de dependência

```text
ADAPTERS
   ↓
APPLICATION
   ↓
DOMAIN
```

O Domain não deve conhecer adapters. As dependências devem apontar para dentro, em linha com a Arquitetura Hexagonal aceita em ADR-003.

## Observações

- Este documento registra as boundaries mínimas sustentadas pelos ADRs aceitos.
- Não foram introduzidas novas boundaries além das já suportadas pela arquitetura hexagonal.
